# Retrofit Directory

A searchable directory of UK housing-retrofit organisations, built for the
[INHABIT / National Retrofit Hub](https://retrofit-directory.org.uk) project at
the University of Surrey.

Users can ask plain-English questions about organisations in the directory
("Which architects are based in Hampshire?") or about UK retrofit policy and
guidance ("What does the Heat and Buildings Strategy say about heat pumps?").
Organisation answers come from a SQLite database populated from a Qualtrics
survey export; policy answers come from a Bedrock Knowledge Base over uploaded
policy PDFs.

---

## Architecture

```text
Browser
  │  HTTPS POST /retrofit/query
  ▼
Apache httpd  (TLS termination, reverse proxy)
  │  HTTP POST http://localhost:5001/api/query
  ▼
Node.js query server  (backend/query.mjs, port 5001)
  │
  ├─ optional multi-turn reformulate (cheap Bedrock model)
  ├─ proximity intercept (deterministic near/nearest; no LLM)
  ├─ intent: heuristic first, else Bedrock Haiku
  │       → directory | policy | out_of_scope
  │
  ├─ directory ── text-to-SQL (canonical orgs_llm schema) ──► SQLite
  │                 └── template answer when shape is simple;
  │                     free-form NL answer only as fallback
  │                 └── on SQL error: one repair pass with full schema
  │
  └─ policy ──── RetrieveAndGenerate ──► Bedrock Knowledge Base
                                         (S3 policy PDFs, eu-west-2)
```

| Layer | File / location |
| --- | --- |
| Static website | `website/` served by Apache from `DocumentRoot /data/retrofit-directory` |
| Apache config | `/etc/httpd/conf.d/retrofit-directory.conf` |
| Node.js backend | `backend/query.mjs` |
| systemd unit | `backend/ops/retrofit-query-server.service` (symlinked to `/etc/systemd/system/`) |
| Database | `backend/directory.db` (generated by `backend/csvToDB.mjs`) |
| Text-to-SQL schemas | `backend/directory.schema.canonical` (default) and `backend/directory.schema` (SQL repair) |
| Tests | `backend/test/` |
| KB metadata tooling | `backend/gen-metadata/` |
| Policy corpus files | `backend/Policies/` (local; not required on the query host) |
| Policy corpus (runtime) | Bedrock Knowledge Base in `eu-west-2` (S3-backed) |
| Backend runbook | `backend/README.md` (layout, ops, tests) |

### Query latency (directory path)

Successful directory answers are optimised to minimise sequential Bedrock calls:

1. **Heuristic intent** skips the route LLM for clear directory / policy / out-of-scope questions.
2. **Proximity** (near / nearest) runs before routing and needs no LLM.
3. **Canonical-only SQL prompt** (`directory.schema.canonical` ≈ orgs_llm only) cuts SQL prompt size roughly in half versus the full raw survey schema.
4. **Template answers** for empty results, counts, name lists, and small multi-column profiles skip a second “answer/wrapper” LLM call.
5. **Full schema** is used only on the optional SQL **repair** pass after a SQLite error.

Typical local measurements after these changes: many directory questions complete in about **0.8–2 s** (one Haiku SQL call). Policy answers remain dominated by Knowledge Base `RetrieveAndGenerate` (often ~3–4 s). Exact times vary with Bedrock load and region.

## Prerequisites

- Node.js ≥ 18
- AWS credentials in `eu-west-2` with:
  - `bedrock:InvokeModel` for `eu.anthropic.claude-haiku-4-5-20251001-v1:0`
    (and the Qwen model used for multi-turn reformulation)
  - `bedrock:Retrieve` and `bedrock:RetrieveAndGenerate` on the configured
    knowledge base
- Apache httpd with `mod_proxy`, `mod_proxy_http`, and `mod_ssl`
- Let's Encrypt certificate (managed by Certbot)

## Backend setup

### Install dependencies

```bash
cd backend
npm install
```

Useful npm scripts (optional):

```bash
npm start                 # node query.mjs
npm run import -- path/to/export.xlsx
npm run rebuild-view      # refresh orgs_llm + schema files without full re-import
npm test                 # offline unit tests
npm run test:security    # live HTTP + Bedrock
```

### Build the database

Import the Qualtrics Excel or CSV export and generate schema annotation files:

```bash
node backend/csvToDB.mjs [path to Qualtrics export file; default: ../directory.csv]
```

The import step creates:

- table `orgs` (survey columns + ONSPD enrichment when available)
- view `orgs_llm` — rich semantic aliases for text-to-SQL (name, type, place,
  activities, specialisms, audience `works_with_*` columns, schemes delivered,
  contacts, …)
- `directory.schema` — full annotated schema (raw `orgs` + `orgs_llm`), used on SQL repair
- `directory.schema.canonical` — `orgs_llm` only, used for default text-to-SQL

If you change view mappings without re-importing the survey:

```bash
cd backend
node rebuild-orgs-llm.mjs
```

#### HQ place enrichment (ONSPD)

If an ONS Postcode Directory zip is present at `backend/geo/ONSPD_*.zip`, import
resolves each organisation headquarters postcode to:

- `local_authority` — ONS local authority district (e.g. Wokingham)
- `parish` — civil parish when available
- `hq_latitude` / `hq_longitude` — postcode centroid

These fields are stored on `orgs`, exposed on `orgs_llm`, and preferred by
text-to-SQL for “in / based in place” questions. Survey `county` is kept as
the self-reported value.

ONSPD is free under the Open Government Licence (Open Geography portal). Place
the zip only on the machine that runs `csvToDB` (gitignored); production needs
only the rebuilt `directory.db` (and both schema files if you deploy them beside
the DB). Re-run enrichment on every weekly survey import so new postcodes are
resolved automatically. Refresh the ONSPD zip roughly quarterly.

```bash
mkdir -p backend/geo
# Download latest ONSPD zip from the Open Geography portal into backend/geo/
node backend/csvToDB.mjs [path to Qualtrics export]
```

#### Weekly refresh (import → verify → optional deploy)

For recurring Qualtrics updates, use the wrapper (requires `backend/geo/ONSPD_*.zip`):

```bash
# Local rebuild + integrity checks only
backend/ops/refresh-directory.sh path/to/qualtrics-export.xlsx

# Same, then scp directory.db to production
backend/ops/refresh-directory.sh path/to/qualtrics-export.xlsx --deploy
```

The script fails if the postcode→`local_authority` match rate for non-blank HQ
postcodes falls below **0.95** (override with `--min-match-rate 0.90` or
`MIN_MATCH_RATE`). It also fails if ONSPD is missing unless `SKIP_ONSPD_CHECK=1`.
After `--deploy`, restart `retrofit-query-server` on the host if it keeps a DB
handle open across replaces. If production also needs updated schema files after
a view-mapping change, copy `directory.schema` and
`directory.schema.canonical` as well (or run `rebuild-orgs-llm.mjs` on the host).

#### Proximity search (near / nearest)

Questions such as “organisations in and near Reading”, “within 10 miles of
Oxford”, or “nearest installer to Guildford” are handled **deterministically**
(not via free-form Haversine SQL from the LLM):

1. `backend/lib/proximity.mjs` detects near/nearest intent and optional type filters
   (installer, architect, …).
2. `backend/lib/geocode.mjs` resolves the place (seed gazetteer → disk cache →
   [postcodes.io](https://postcodes.io)).
3. Crow-flies distance is computed in Node against `hq_latitude` / `hq_longitude`
   already stored on `orgs_llm`.

Default “near” radius is **25 miles**. Exact “in Wokingham” style questions still
use text-to-SQL on `local_authority` / `parish` / `county` / `operating_areas`.
Offline checks:

```bash
node backend/test/test-proximity.mjs
```

Or copy the database alone:

```bash
backend/ops/deploy-directory-db.sh
```

### Run as a systemd service

```bash
sudo cp backend/ops/retrofit-query-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now retrofit-query-server
```

Logs are written to the system journal:

```bash
sudo journalctl -u retrofit-query-server -f
```

### Run manually (development)

```bash
VERBOSE=1 ADMIN_PASSWORD=<<admin password>> node backend/query.mjs
# Listens on http://127.0.0.1:5001
```

## API

### `POST /retrofit/query` (via Apache) or `POST /api/query` (direct)

#### Request

```json
{
  "messages": [
    { "role": "user", "content": [{ "query": "How many organisations are based in Bristol?" }] }
  ]
}
```

Constraints enforced server-side:

| Constraint | Value |
| --- | --- |
| `messages[messages.length-1].content[0].query` must be a string | 400 if missing or wrong type |
| Maximum `query` length | 500 characters |
| Maximum request body | 8 KB |
| Rate limit | 20 requests per IP per minute |

#### Response (success)

Directory lookup (sources intentionally empty):

```json
{ "response": "There are 4 organisations based in Bristol: …", "sources": [] }
```

Policy / guidance lookup (citations from the knowledge base when available):

```json
{
  "response": "According to the Heat and Buildings Strategy…",
  "sources": [{ "name": "Heat and Buildings Strategy", "url": "https://…" }]
}
```

Only the natural-language `response` (and policy `sources`) is returned to users.
Generated SQL and raw database rows are logged server-side only and never sent
to the client.

The backend classifies each question as `directory`, `policy`, or
`out_of_scope` before answering (heuristic rules first; Bedrock only when
ambiguous). Out-of-scope questions return a friendly scope message in
`response` rather than failing with a 500.

#### Error responses

| HTTP status | Meaning |
| --- | --- |
| 400 | Missing, wrong-type, empty, or over-length query |
| 413 | Request body exceeds 8 KB |
| 429 | Rate limit or daily Bedrock token budget exceeded |
| 500 | Internal server error |

## Security hardening

### Admin usage endpoint

`POST /api/observe` requires `Authorization: Bearer <token>` matching the
server environment variable `ADMIN_PASSWORD`. If the variable is unset the
endpoint returns `503`. Configure it via systemd:

```bash
sudo systemctl edit retrofit-query-server
# [Service]
# Environment=ADMIN_PASSWORD=your-long-secret
sudo systemctl restart retrofit-query-server
```

The admin page stores the token in `sessionStorage` for up to 12 hours after a
successful unlock. It is not a substitute for network access controls on the
admin path.

The following controls are currently implemented.

### Input validation

All incoming `query` values are validated before any processing:

- Must be a non-empty, non-whitespace `string` (rejects numbers, booleans, objects)
- Maximum 500 characters — prevents oversized prompts being sent to Bedrock
- Request body capped at 8 KB via `express.json({ limit: '8kb' })`

### Prompt sanitisation

Double-quote (`"`) and backslash (`\`) characters are replaced with spaces
before the user's query is interpolated into the LLM prompt strings.  This
prevents prompt-delimiter break-out attacks (e.g. injecting `"` to close the
quoted `User Question:` field and append adversarial instructions).

### LLM-output SQL validation (`validateSql`)

The SQL string returned by the LLM is validated before it is executed:

- Line and block comments (`-- …`, `/* … */`) are stripped before checks
- Exactly one statement is allowed (at most one trailing `;`; no stacked SQL)
- The statement must begin with `SELECT` or `WITH` (word-boundary, case-insensitive)
- Forbidden keywords anywhere in the statement include `DROP`, `INSERT`,
  `UPDATE`, `DELETE`, `ALTER`, `CREATE`, `ATTACH`, `PRAGMA`, `INTO`, and similar
- Result sets are capped at 500 rows server-side
- Rejected SQL causes a friendly out-of-scope response; the SQL is logged
  server-side for review

This is a defence-in-depth measure on top of opening the directory database
`OPEN_READONLY`.

### SQL reliability guardrails

To reduce schema-mapping and runtime failures in text-to-SQL generation:

- Default SQL prompts use only the canonical `orgs_llm` schema file.
- If canonical alias columns are used but `FROM orgs` is generated, the backend
  rewrites the query to `FROM orgs_llm`.
- For simple organisation-name list queries, `SELECT DISTINCT` is enforced to
  suppress duplicate names unless duplicates are explicitly requested.
- If the first SQL execution fails, the backend performs one regeneration pass
  using the **full** schema plus the SQLite error message as feedback, then retries once.

### Deterministic directory answers

For common result shapes, the backend formats answers without a second LLM call:

- Empty results, single numeric counts, single-column lists (any length), and
  small multi-column profiles are rendered with templates (exact counts preserved).
- Free-form natural-language generation is used only when the result shape is
  too awkward for a template.

This keeps directory latency closer to a single model round-trip while avoiding
count mismatches in list outputs.

### Read-only database connection

The SQLite database is opened with `sqlite3.OPEN_READONLY`.  Even if the SQL
validation were somehow bypassed, no write operation could succeed.

### Rate limiting

`express-rate-limit` applies:

- **20 requests per IP per minute** to `/api/query`
- **30 requests per IP per minute** to `/api/observe`

Requests that exceed the limit receive a `429 Too Many Requests` response.

### Daily Bedrock token budget

Before any model call, `/api/query` checks the sum of input+output tokens
logged for the current **UTC** day in `usage.db`. The default budget is
**200,000 tokens**. Override with `DAILY_TOKEN_BUDGET` (set `0` to disable).
When the budget is exhausted the endpoint returns `429` with a clear message
and does not call Bedrock.

### Request logging

Verbose per-request console logging is **off by default**. Set `VERBOSE=1`
(or `true` / `yes`) on the process to enable detailed query/SQL logs.

### Loopback-only binding

The Node.js server binds exclusively to `127.0.0.1`.  Port 5001 is not
reachable from outside the host; all public traffic must pass through the
Apache TLS proxy.

### CORS policy

CORS is currently restricted to the following allowed origins:

- `https://retrofit-directory.org.uk`
- `https://www.retrofit-directory.org.uk`
- `http://localhost`
- `http://127.0.0.1`

### Clean error responses

A global Express error handler ensures that middleware-level errors (such as
`PayloadTooLargeError`) return a plain JSON body (`{"error":"…"}`) rather than
an HTML stack trace that would reveal internal file paths and package versions.

### Apache recommendations (apply manually)

Add the following to the `<VirtualHost *:443>` block in
`/etc/httpd/conf.d/retrofit-directory.conf`:

```apache
# Reject oversized request bodies at the proxy layer
LimitRequestBody 8192

# Prevent MIME-type sniffing and clickjacking
Header always set X-Content-Type-Options "nosniff"
Header always set X-Frame-Options "DENY"
Header always set Referrer-Policy "strict-origin-when-cross-origin"
```

Also review the SSL protocol and cipher configuration with
[SSL Labs](https://www.ssllabs.com/ssltest/) and restrict to modern-only
ciphers (`TLSv1.2`/`TLSv1.3`).

## Security tests

A regression test script covers the controls above:

```bash
# Test the Node.js service directly (no Apache)
./backend/test/test-security.sh

# Test through Apache / the public URL
./backend/test/test-security.sh https://retrofit-directory.org.uk/retrofit
```

The script exits with a non-zero code if any test fails, making it suitable
for use in a CI pipeline. It exercises the current `messages` / `response`
request shape, hardened `validateSql` cases, and rate limits on both
`/api/query` and `/api/observe`. Note: the query rate-limiting section sleeps
61 seconds to guarantee a clean window; total runtime is approximately two
minutes including two Bedrock calls.

## Policy corpus tooling

Scripts under `backend/gen-metadata/` prepare documents and Bedrock Knowledge
Base sidecar metadata. Document files and sidecars live under
`backend/Policies/`. Run from `backend/` (paths in the scripts resolve to
`../Policies` relative to `gen-metadata/`). Sidecars follow Bedrock’s
`<document>.metadata.json` convention so attributes such as `display_name`,
`title`, `year`, `url`, and `doc_type` travel with each uploaded object.

### Fetch a public webpage (`gen-metadata/fetch-policy-page.js`)

Uses [trafilatura](https://github.com/adbar/trafilatura) to extract Markdown
and metadata, then writes:

- `backend/Policies/<name>.md`
- `backend/Policies/<name>.md.metadata.json`

```bash
cd backend
node gen-metadata/fetch-policy-page.js <url>
node gen-metadata/fetch-policy-page.js --url <url>
node gen-metadata/fetch-policy-page.js --dry-run <url>
node gen-metadata/fetch-policy-page.js --name custom-slug <url>
node gen-metadata/fetch-policy-page.js --help
```

### Interactive webpage metadata (`gen-metadata/write-metadata.js`)

Prompts for display name, year, title, URL, and file name, then writes:

- `backend/Policies/<file name>.pdf.metadata.json`

```bash
cd backend
node gen-metadata/write-metadata.js
```

### Zotero RDF → PDF sidecars (`gen-metadata/generate-policy-metadata.js`)

Reads a Zotero RDF/XML export (default under `backend/Policies/`) and writes
sidecars for PDFs already present there:

- `backend/Policies/<pdf-filename>.metadata.json`

```bash
cd backend
node gen-metadata/generate-policy-metadata.js
node gen-metadata/generate-policy-metadata.js --dry-run
node gen-metadata/generate-policy-metadata.js [rdf-path]
node gen-metadata/generate-policy-metadata.js --rdf <path>
node gen-metadata/generate-policy-metadata.js --help
```

### S3 metadata index (`gen-metadata/list-document-metadata.js`)

Downloads Bedrock KB sidecar objects from S3 (via the AWS CLI) and writes a
sorted index. Each output line is:

```text
[display_name] [url]
```

```bash
cd backend
node gen-metadata/list-document-metadata.js
node gen-metadata/list-document-metadata.js --out ./document-index.txt
node gen-metadata/list-document-metadata.js --bucket retrofit-directory-documents --region eu-west-2
node gen-metadata/list-document-metadata.js --help
```

Requires AWS credentials with read access to the documents bucket. Defaults
for bucket/region/prefix are defined in the script header and `--help` text.

## Directory import and ops CLIs

Narrative setup lives under [Backend setup](#backend-setup). This section is a
compact command reference; each script also documents itself in its file header.

### Import Qualtrics export (`csvToDB.mjs`)

```bash
cd backend
node csvToDB.mjs
node csvToDB.mjs path/to/qualtrics-export.xlsx
node csvToDB.mjs path/to/qualtrics-export.csv
```

**Outputs:** `directory.db` (table `orgs`, view `orgs_llm`),
`directory.schema`, and `directory.schema.canonical`. Default input is
`../directory.csv`. With `backend/geo/ONSPD_*.zip` present, HQ postcodes gain
`local_authority`, `parish`, `hq_latitude`, and `hq_longitude`.

### Rebuild view only (`rebuild-orgs-llm.mjs`)

```bash
cd backend
node rebuild-orgs-llm.mjs
```

Recreates `orgs_llm` and both schema files from the current `orgs` table
without re-reading the Qualtrics export. Use after mapping changes in
`lib/orgsLlmView.mjs`.

### Verify import (`verifyImport.mjs`)

```bash
cd backend
node verifyImport.mjs
node verifyImport.mjs path/to/qualtrics-export.xlsx
node verifyImport.mjs [inputPath] [dbPath] [schemaPath]
```

Compares the source spreadsheet to `directory.db` / schema files and
checks enrichment and `orgs_llm` aliases. Prints `OK` / `NOTE` / `ISSUE` lines;
exits non-zero on failure.

### Weekly refresh wrapper (`refresh-directory.sh`)

```bash
cd backend
./ops/refresh-directory.sh path/to/export.xlsx
./ops/refresh-directory.sh path/to/export.xlsx --deploy
./ops/refresh-directory.sh path/to/export.xlsx --deploy --min-match-rate 0.90
./ops/refresh-directory.sh -h
```

Runs import → postcode→LA match-rate gate (default **0.95**) → verify →
optional deploy. Environment: `MIN_MATCH_RATE`, `SKIP_ONSPD_CHECK=1`.

### Deploy database only (`deploy-directory-db.sh`)

```bash
cd backend
./ops/deploy-directory-db.sh
```

`scp`s `./directory.db` to `AWS-CRESS:/data/retrofit-directory/backend/directory.db`.
Requires the SSH host alias and a local `directory.db`. Restart
`retrofit-query-server` on the host if needed after replace.

### Query server (`query.mjs`)

```bash
cd backend
VERBOSE=1 ADMIN_PASSWORD=secret node query.mjs
# production: systemd unit backend/ops/retrofit-query-server.service
```

**Endpoints:** `POST /api/query`, `POST /api/observe` (Bearer `ADMIN_PASSWORD`).
**Environment:** `PORT` (default 5001), `ADMIN_PASSWORD`, `DAILY_TOKEN_BUDGET`,
`VERBOSE`. Needs `directory.db`, schema files (`directory.schema.canonical`
preferred for SQL; full schema for repair), and Bedrock credentials.

### Supporting libraries (not CLIs)

| Module | Role | Used by |
| --- | --- | --- |
| `lib/orgsLlmView.mjs` | Canonical view mappings + schema export | `csvToDB.mjs`, `rebuild-orgs-llm.mjs` |

## Tests and smoke scripts

All live under `backend/test/`.

### Offline unit tests

```bash
cd backend
node test/test-validate-sql.mjs   # SQL guardrails (no network)
node test/test-proximity.mjs      # geocode + proximity (needs directory.db with HQ coords)
# or: npm run test:offline
```

Exit code is the failure count (`0` = all pass).

### Security regression suite (`test/test-security.sh`)

```bash
cd backend
./test/test-security.sh
./test/test-security.sh http://localhost:5001/api/query
./test/test-security.sh https://retrofit-directory.org.uk/retrofit
# or: npm run test:security
```

Automated checks for bind address, validation, body limit, `validateSql`,
prompt-injection smoke, response shape, and rate limits. ~2 minutes (includes
a 61s sleep and live Bedrock calls). Exit non-zero on any failure.

```bash
cd backend
```

Not a pass/fail harness — use for quick eyeballing while developing.
